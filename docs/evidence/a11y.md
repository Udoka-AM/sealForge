# Accessibility pass (task 5.4)

**Tool:** axe-core 4.10.2. Rule sets: WCAG 2.0 A/AA, 2.1 AA, 2.2 AA, plus best practices.
**Setup:** run in the browser against the dev server and the local regtest coordinator (2026-10-15), with real data on every page.

| Page | Violations |
|---|---|
| `/` Home | 0 |
| `/a/{code}` Auction (open and settled) | 0 |
| `/a/{code}/bid`: amount and refund address | 0 |
| `/a/{code}/bid`: pay step (QR) | 0. Focus moves to the step heading |
| `/verify` | 0 |
| `/audit/{code}` | **3 serious before, 0 after**: `definition-list` and `dlitem` (nested `div > div > dt`), and `scrollable-region-focusable` (a scrolling `<pre>`). Fixed by flattening the list and wrapping long commands instead of scrolling them |
| `/me` | 0 |
| `/how-it-works` | 0 |
| `/console`, `/console/new`, `/console/{code}` | 0 (the console's command block was changed to wrap as well) |
| `/trustee/{code}` | 0 |
| 404 | 0 |

Colour contrast was evaluated (for example, 11 elements passed on the closed bid page). No element has a positive `tabindex`.

**Keyboard order on the bid form:** header links, auction link, **Maximum bid**, **Refund address**, **Continue**. Every control is a native element with a visible label, and the focus ring is the 2 px gold outline from `globals.css`.

**Still to do on staging:** Lighthouse accessibility score (target ≥ 95) on the deployed build, and a manual screen-reader pass (VoiceOver) of the bid flow.
